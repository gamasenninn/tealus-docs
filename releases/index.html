    リリースノート¶

    このページは 「使う人」向けの要約です。各リリースで何が変わったか、そして更新するときに何をしないと壊れるかを短く載せます。

    • 実装の詳細と設計判断の理由 → 本体リポジトリの CHANGELOG
    • 自己ホスト環境の具体的な更新手順 → 本体リポジトリの アップグレードガイド

    このページの形式について

    以前は本体 CHANGELOG とほぼ同じ内容を二重に持っていましたが、二重管理は必ず片方が腐り、腐ったときに読者がどちらを信じてよいか判断できません。そのため詳細は CHANGELOG に一元化し、このページは要約とリンクに絞る方針へ切り替えました。

    v0.4.0 以降がこの新しい形式です。v0.3.0 以前は当時の詳細な記述をそのまま残しています。また、新しい機能はガイドページの整備が追いついていないものがあります（tealus-docs#17 で対応中）。

    v0.7.0 — 出したものが端末に届き、使うほど指示が短くなる（2026年7月31日）¶

    iOS の PWA に更新が届かない構造的な問題を根治し、あわせてエージェントへの指示を「登録」させず過去の自分の投稿から再利用できるようにしたリリースです。

    主な変更

    • PWA 更新検知（#355 / #356）— 新しいクライアントが自分の陳腐化に気づいて更新バナーを出すようになりました。プロフィール画面の下部にビルド ID が常時表示され、実機が新旧どちらかを目視で判定できます
    • エージェント指示の履歴ピッカー（#354 / #357 / #358）— 🤖 パネルに「最近の指示」が出ます。登録は不要で、過去に自分が送った @アシスタント / @cc-* 宛のメッセージをそのまま再利用できます。PC では / → ↑ がシェルの履歴と同じ操作です。「直近の画像 N 枚で〜」のように数字だけが変わる指示は 1 件にまとまり、変わる位置だけが選択状態で挿入されます（挿入するだけで、送信はしません）
    • ルームのタグ削除（#351）— 従来は追加のみでしたが、タグ画面の「管理」トグルから削除できるようになりました
    • LINE の複数画像を 1 メッセージにまとめる（#353）— 順不同で別々に届く画像を待ち合わせて 1 件に再構成します（待ち時間は LINE_IMAGESET_FLUSH_MS、既定 15 秒）。詳細は LINE Bridge 連携
    • organon なしでも語彙の正規化が効く（#348 / #349）— 辞書テーブルから dictionary.local.ttl を発行し、エージェントはこれを優先して読みます。organon を導入していない環境でも別名→正規名の正規化が生き続けます

    ★ 更新時の急所

    • DB migration の追加はゼロです
    • ★ cd client && npm run build — 再ビルドしないと更新検知そのものが入りません（エラーにはならず、静かに機能しません）
    • ★ cd agent-server && npm install + 再起動 — 依存に n3 が追加されました。忘れると agent-server が起動時に落ちます
    • ★ この版に上げるときだけ、各端末で 1 回だけ手動リロードが必要です（旧クライアント側に更新を検知する手段がないため）。次回以降はバナーが自動で出ます
    • リバースプロキシを挟んでいる場合、index.html / sw.js / *.webmanifest の Cache-Control をプロキシ側が上書きしていないか確認してください

    v0.6.0 — AI に「構造」を渡す（2026年7月21日）¶

    AI に定型の確認や判断を集めさせるための汎用フォームと、「アシスタントに聞いたつもりが無反応だった」を減らすエージェントの起動入口が入りました。

    主な変更

    • 汎用フォーム（#336）— ルームに回答フォーム（単一選択 + 自由記述）を投稿できます。回答者が [回答する] を押すと、回答が返信として投稿されると同時に担当エージェントが起動します（コピペ + 手書き + 別途メンション、が 1 ボタンに畳まれます）。MCP からは send_form（MCP Server）
    • エージェント起動入口（#338）— 入力欄の 🤖 ボタン / メッセージ長押しの「エージェントに送る」で正しい宛先が自動で入ります。呼び忘れたメッセージを編集して先頭にメンションを足すと、そこから起動します
    • 未適用 migration の起動時 warn（#334、採用者保護）— migration を忘れた状態でも起動してしまい、機能だけが静かに欠ける事故を、起動ログの [migration-check] で可視化しました
    • エージェント受付の可視化（#335）— @cc-* を投げたときに「届きました」と表示が出るようになり、「反応が返るのか分からないまま待つ」状態が解消しました

    直った不具合 — スリープ復帰後に「考え中 / 入力中」が残る（#340）／フォームの回答ボタンが何度も押せる二重回答（#341）

    ★ 更新時の急所

    • ★ cd server && npm run migrate — 追加は 026_message_form_type.sql の 1 本。忘れるとフォーム投稿が DB 制約で失敗します
    • ★ cd client && npm run build — フォーム UI と起動入口が入っているため再ビルド必須
    • cd agent-server && npm install + 再起動
    • MCP から send_form を使う場合は tealus-mcp v0.14.8 以上（タグ固定運用なら pin 更新 + Claude Code のフル再起動）。本体の更新だけでは MCP クライアント側は変わりません

    v0.5.0 — TypeScript 化と、自己成長する辞書（2026年7月14日）¶

    コードベース全体の TypeScript 化という土台の入れ替えと、人の修正履歴から別名を自動で学習していく辞書が入った、範囲の大きいリリースです。

    主な変更

    • コードベース 100% TypeScript 化（#330）— 全レイヤーを .mts / .ts 化し、サーバーはビルドせず直接実行する構成になりました（型検査は別途 tsc --noEmit）。★ この変更により Node 24 が必要です（サーバー構築）
    • 自己成長する変換辞書（#327）— 別名→正規名の辞書がファイルから DB テーブルへ移りました。人が文字起こしを直した履歴から別名を自動学習し、精度の基準を満たしたものだけが実際に効き始めます。管理ダッシュボードに承認 / 却下の育成画面が付きました（ダッシュボード）
    • 自ホスト STT + organon 文脈補正（#326）— TRANSCRIPTION_MODE=organon で、自ホストの音声認識の出力を組織の語彙で補正する 2 段構成に切り替えられます（データ主権を保ったまま固有名詞を回収する構成）
    • organon から辞書を自動取り込み（#331）— organon 側の更新が 5 分以内に辞書と文字起こしへ自動反映されます
    • 画像・帳票まわりの強化 — 貼り付け（Ctrl+V）でのアップロード（#311）／1 メッセージの複数画像・複数文書をすべて読めるように（#316 / #317、従来は 1 件目だけ）／業務語彙を画像 OCR にも効かせる VOCAB_INJECT（#315、既定 OFF）
    • 完了を表す ✅ リアクションと、その抽出（#323 / #325）— 「✅ が付いていないもの一覧」をエージェントが確実に絞り込めるようになりました
    • Deep のタイムアウトを 5 分 → 8 分に延長（#314）

    直った不具合 — 音声認識が日本語を中国語と誤検出して文字起こしが壊れる（#332）／日本語ファイル名の文字化け（#319）／画像生成が全失敗（#313、gpt-image-1 へ移行）／「ルーム情報の取得に失敗しました」の頻発（#322、通信の間欠停止に対するリトライ）

    ★ 更新時の急所

    • ★ Node 24 が必要です。 TypeScript 化により、型注釈をそのまま解釈できない版では起動しません。24 未満では npm install 自体が EBADENGINE で止まります（サーバー構築 > 前提条件）
    • ★ cd server && npm run migrate — 辞書テーブルの 023〜025 が追加されました。忘れると辞書育成タブが 500 になり、自己成長辞書が静かに効きません（この事故を可視化する起動時 warn は次の v0.6.0 で入りました）
    • cd client && npm run build + 全パッケージの npm install と再起動

    このリリースはアップグレードガイド（v0.6.0 で新設）のバージョン別ノートより前のため、上記は CHANGELOG からの要約です。

    v0.4.0 — 外部チャネル連携と、room を越える AI 協働（2026年6月21日）¶

    LINE からの投稿を取り込む外部連携と、AI が room の境界を越えて協働するための明示構文が入りました。

    主な変更

    • LINE Bridge（受信）（#288 〜 #291 / #309）— LINE 公式アカウントへの投稿を Tealus のルームに取り込みます。テキスト / 画像 / 音声（自動で文字起こし）/ 動画 / ファイル / スタンプ / 位置情報の 7 種に対応。詳細は LINE Bridge 連携
    • %委譲% — room 間の AI 委譲（#295 / #292）— 「どう頼んだか」の言い回しに依存せず、明示構文で確実に他ルームの AI へ委譲できます。複数ルームへの同時委譲も可能です。詳細は Agent ガイド
    • Light の backend を設定で切り替え可能に（#292）— AGENT_LIGHT_BACKEND で v1 / v2 を選べるようになり、既定が v2 に変わりました。詳細は Agent ガイド
    • アクセスログ（#301）— 管理ダッシュボードに最終投稿 / 最終閲覧の集計ビュー。詳細は ダッシュボード
    • ゲスト role の運用開始（#282）— 外部の問い合わせ者向けに、見える範囲を絞った役割を運用可能にしました。詳細は AIエージェント設定
    • メッセージの部分コピー（#308）／文字起こしの連続編集（#302、前後の音声へ送りながら編集）／長文 TTS の失敗防止（#300、TTS 読み上げ）

    直った不具合 — 「考え中」表示が残り続ける / 他ルームに漏れる（#298 / #297）／1 件の描画エラーでチャット全体が白紙化する（#306）／送信に失敗しても「送信済み」に見える（#303）／Codex の認証トークンが繰り返し失効する（#307）

    ★ 更新時の急所

    • DB migration の追加はゼロです
    • ★ organon を使っている場合、環境変数の名前と既定値が変わりました（#304）。INJECT_ORGANON_POLYSEME（既定 ON）は廃止され、ORGANON_INJECT=true（既定 OFF の opt-in）になりました。互換の読み替えはないため、旧名のままでは何も注入されずに静かに動きます
    • ★ Light の既定 backend が v1 → v2 に変わりました。 従来どおり v1 で運用したい場合は AGENT_LIGHT_BACKEND=v1 を明示してください
    • cd client && npm run build + 再起動

    このリリースはアップグレードガイド（v0.6.0 で新設）のバージョン別ノートより前のため、上記は CHANGELOG からの要約です。

    v0.3.0 — 「組織記憶辞書が動作する道具に転化した release」（2026年6月1日）¶

    Phase 4 organon paradigm operational realization 完成。Day 14-15-16（5/30-6/1）で Codex Deep agent + organon polyseme inject pipeline + 5/16 ground truth pattern 解消 + 4 Issue cluster 連続 close を達成、organon が業務 DB を upstream rectification する thesis が structural に完成 した転換点 release。

    5/12 v0.2.4 → 5/19 organon Day 3 量的成功 → 5/30 Day 14 organon 日次サイクル workflow 化 → 5/31 Day 15 Codex Deep + polyseme inject pipeline 完成 → 6/1 Day 16 release cut の 20 日間の進化 を集約。

    Codex Deep agent + Light backend config 化 + cross-room delegation¶

    • Codex Deep agent (deepCodex.js) 追加 + DEEP_AGENT_PROVIDER で切替（#276、5/31 Day 15、commit 41b0f55）: 既存 Deep agent（claude -p spawn）と並列で codex exec spawn 経路を追加。Light v2 で確立した Codex SDK / subscription auth pattern を CLI mode で再現
      • env DEEP_AGENT_PROVIDER=claude|codex（default=claude、既存維持）で switch
      • env DEEP_CODEX_AUTH=subscription|api-key（default=subscription）で ~/.codex/auth.json 経由 ChatGPT subscription 認証 = API cost 0（Deep mode の 12-50k tokens × call 課金爆発 risk 回避 default）
      • CODEX_HOME 動的切替（workspace 配下 .codex_home/）、AGENTS.md（= CLAUDE.md literal copy、Codex CLI 自動 read project context、上限 32 KB）

    Node.js 20+ 必須化（破壊的変更）

    ★ これは当時の要件です。 v0.5.0 の TypeScript 化（#330）以降、現在の要件は Node 24 です（サーバー構築 > 前提条件 参照）。

    • 初回ユーザー auto-promote（#211）: 最初の非 Bot ユーザー（is_bot=false の COUNT が 0）が登録時に自動 admin role に。Mattermost / Rocket.Chat / GitLab 標準の OSS first-user-admin パターン
