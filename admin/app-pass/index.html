    アプリの通行証と「Tealus でログイン」¶

    v0.12.0 で入った、ほかのサイトに Tealus の ID で入るための 2 つの仕組みです。どちらも、管理者が相手のサイトを決めて鍵を置いたときだけ動きます。既定では何も起きません。

    仕組み 何が楽になるか 誰に出すか
    アプリの通行証（#607） アプリパネルとホームのタブで開くアプリの、ベーシック認証のパスワードを打たずに済む 部屋のアプリ: その部屋のメンバー。ホームのタブ: ログイン中の人
    ブラウザから「Tealus でログイン」（#648） Tealus のアプリを開いていない人も、ブラウザで相手のサイト（社内のポータルなど）に Tealus の ID で入れる ログイン中の人

    どちらも、ゲストと機械のアカウント（bot）には出しません。

    Tealus がするのは、短い期限の署名つきの札を作って相手のサイトへ渡すところまでです。札を確かめてログインやクッキーを渡すのは、相手のサイトの仕事です（相手のサイトがすること）。

    しくみ¶

    アプリの通行証¶

    1. 利用者が、通行証の印が付いたアプリを開く
    2. Tealus の画面が本体に通行証を頼む。本体は、条件を満たせば 2 分だけ有効な通行証を作る
    3. アプリの枠が https://<アプリのサイト>/tealus-gate/?tealus_pass=<通行証> を開く
    4. 相手の入口（/tealus-gate/）が通行証を確かめ、自分のクッキーを渡して、アプリのページへ移る

    アプリを開き直すたび（パネルを閉じて開く・タブを替える）に、新しい通行証を取ります。

    ブラウザから「Tealus でログイン」¶

    1. 相手のサイトが合言葉（state）を作って自分のクッキーに置き、https://<Tealus>/sso/app-login?aud=<相手の origin>&state=<state> へ移す
    2. Tealus にログインしていなければ、ログイン画面が出る。ログインすると、同じページに戻る
    3. 本人が「<相手のホスト名> にログインする」を押す
    4. 本体が 60 秒だけ有効なログインの札を作る。画面は、管理者が決めた戻り先 <相手の origin><戻り先のパス>?tealus_login=<札> へ移る
    5. 相手のサイトが札を確かめ、自分のログインを渡す

    戻り先は本体の設定だけが決めます

    戻り先のパスは、相手のサイトから URL で受け取りません。APP_LOGIN_TARGETS に書いたものだけを使います。

    管理者がすること¶

    1. 相手のサイトごとに鍵を置く¶

    鍵は、2 つの仕組みで同じものを使います。相手のサイトのホスト名ごとに 1 本です。

    • 置き場: APP_PASS_KEY_DIR（未設定なら ~/.tealus/app-pass。本体を動かす利用者のホーム）
    • ファイル名: <ホスト名>.key（例 portal.example.com.key）。小文字のホスト名だけで、https:// もポート番号も付けません
    • 中身: 16 進の 1 行で、32 バイト以上（64 文字以上）。例えば openssl rand -hex 32 で作れます
    • 同じ鍵を、相手のサイトの公開ディレクトリの外に置いてもらいます

    鍵は部屋に貼らない・repo に入れない

    鍵は、本体と相手のサイトが共有する秘密です。知っている人は、だれの札でも作れます。チャットの部屋に平文で貼らず、ファイルのまま受け渡してください。替えるときは両方を同時に替えます。替えた時点で出ていた札は通らなくなります。

    ★ 鍵ファイルの名前や中身がずれると、黙って元の URL で開きます（#607）

    ❌ 誤り ✅ 正しい
    https___portal.example.com.key / portal.example.com:8443.key portal.example.com.key（ホスト名だけ）
    中身が base64・16 進で 63 文字以下 16 進で 64 文字以上の 1 行

    症状: 画面にエラーは出ません。通行証が出ないので、アプリは元の URL で開き、パスワードの箱が出ます。本体の記録には [app-pass] 出さない: … — 鍵が無い (<ホスト名>) が残ります。ログインの札では「このサイトにはログインの札を出せません」が出ます。 再起動: 要りません（鍵ファイルは頼まれるたびに読みます）。ただし APP_PASS_KEY_DIR 自体を変えたときは、本体の再起動が要ります。

    2. アプリに「通行証を添える」を付ける¶

    部屋のアプリパネル — 部屋の管理者（またはシステム管理者）が、トーク画面右上の ≡ → ルーム設定の「ルーム設定（管理者）」→「アプリパネル」で、アプリごとに「Tealus の通行証を添える」をオンにします。既定はオフです。グループの部屋だけで設定できます。

    ホーム画面のタブ — システム管理者が、管理ダッシュボード（/admin）の「ポータル」タブで、リンクの登録・編集に出る「Tealus の通行証を添える」をオンにします。一覧の「状態」に「通行証」の印が付きます。

    ★ http:// のアプリには通行証が出ません（#607）

    ❌ 誤り ✅ 正しい
    http://portal.example.com/app/ に「通行証を添える」 https://portal.example.com/app/

    アプリの URL そのものは http:// でも登録できます。ですが、通行証は https:// のときだけ出します（札を暗号化されない道に乗せないため）。 症状: 印を付けても、パスワードの箱が出たままです（元の URL で開きます）。記録には [app-pass] 出さない: … — https の URL でない… が残ります。 再起動: 要りません（URL を直せばすぐ効きます）。

    3. 「Tealus でログイン」の相手と戻り先を決める¶

    server の .env に APP_LOGIN_TARGETS を書きます。<origin>|<戻り先のパス> をカンマで並べます。既定は空です（だれにも出しません）。

    APP_LOGIN_TARGETS=https://portal.example.com|/auth/callback,https://shop.example.com:8443|/login?from=tealus
    • origin は https:// で、パスも末尾の / も付けない形にします（ポートは付けてよい）
    • 戻り先のパスは / で始めます。// や /\ で始まるもの、# を含むものは読みません
    • 戻り先のパスに ? があれば &tealus_login=…、無ければ ?tealus_login=… を付けて返します
    • 鍵は手順 1 と同じ <ホスト名>.key を使います
    • 書き換えたら、本体を再起動します（.env は起動のときに読みます）

    ★ 崩れた行は、黙って捨てられます（#648）

    • ✅ https://portal.example.com|/auth/callback
    • ❌ https://portal.example.com/|/auth/callback（origin の末尾に /）
    • ❌ http://portal.example.com|/auth/callback（https でない）
    • ❌ https://portal.example.com|auth/callback（パスが / で始まらない）
    • ❌ https://portal.example.com|/auth/#cb（パスに #）

    相手のサイトが送る aud も、ここに書いた origin と1 文字も違わず一致しなければなりません。 症状: 起動のときに警告は出ません。押すと「このサイトにはログインの札を出せません。元のサイトからもう一度お試しください。」が出ます。本体の記録には [app-login] 出さない: aud=… — 許可表に無い aud が残ります。 再起動: 要ります（.env を直したあと本体を再起動）。

    4. migration と再ビルド¶

    • migration 041（041_portal_links_pass.sql）が要ります。ホームのタブに通行証の印の列を足します。v0.12.0 からは、未適用の migration があると本体は起動しません
    • client を本番ビルドし直します。しないと、画面のボタンも通行証も出ません（エラーも出ません）

    使う人に見えるもの¶

    アプリの通行証

    • 印の付いたアプリを開くと、パスワードを聞かれずにアプリが出ます。通行証を取っている間、枠は白いままです
    • 通行証が取れないとき（鍵が無い・ゲストなど）は、元の URL で開きます。今までどおりパスワードの箱が出るだけで、壊れはしません
    • アプリパネルの見出しの ↗ の印（「別のタブで開く」） を押すと、いま選んでいるアプリを、通行証つきで別のタブに開きます。PC で全画面に使うときに便利です
    • ホーム画面のタブの「新タブで開く」は、通行証を付けずに元の URL を開きます（パスワードの箱が出ます）

    ブラウザから「Tealus でログイン」

    • 相手のサイトの「Tealus でログイン」から Tealus の画面に来ます。「Tealus の ID で <ホスト名> にログインします。自分で開いたページでなければ、押さずに閉じてください。」と出ます
    • 「<ホスト名> にログインする」を押すと、相手のサイトに戻ってログインできます
    • Tealus にログインしていなければ、先にログイン画面が出ます。ログインすると、このページに戻ります
    • 出せないとき（ゲスト・機械のアカウント・相手が決まっていない）は、「このサイトにはログインの札を出せません。元のサイトからもう一度お試しください。」が出ます

    押すまで何も起きません

    ログインしていても、本人がボタンを押すまで札は出しません。自分で始めたログインでなければ、押さずに閉じてください。

    相手のサイトがすること¶

    札は HMAC-SHA256 の共有鍵で署名しています。公開鍵・JWKS・確かめるための API はありません。相手のサイトは、手順 1 の鍵を持ち、自分で署名を計算して確かめます。

    札の形¶

    v1.<base64url(中身の JSON)>.<base64url(HMAC-SHA256(鍵, "v1." + base64url(中身の JSON)))>
    • base64url は + → -、/ → _ に替えて、末尾の = を取った形です
    • 署名は、届いた文字列の v1.<中身> の部分そのままで計算します。JSON を組み直してから計算しないでください
    中身 アプリの通行証 ログインの札
    v 1 1
    typ 無い "login"
    aud アプリの origin 相手の origin
    room 部屋の ID。ホームのタブからは "home" 無い
    to 行き先のパスと問い合わせ（例 /app/?mode=a） 無い
    state 無い 相手が作った合言葉（そのまま返す）
    sub / name Tealus の利用者 ID / 表示名 同じ
    iat / exp 出した時刻 / iat + 120（2 分） 出した時刻 / iat + 60（60 秒）

    確かめる順番¶

    1. v1. で始まり、. で 3 つに分かれること
    2. 署名: 自分の鍵で計算し、時間で差が出ない比べ方（PHP なら hash_equals）で比べる。★ ここより前に中身を信じない
    3. 中身の JSON を読み、v が 1、aud が自分の origin と一致すること
    4. exp が過ぎていないこと
    5. 種類で分ける
      • 入口 /tealus-gate/（アプリの通行証）: ★ typ がある札は落とす。to が / で始まり、//・/\ で始まらないこと。通ったら自分のクッキーを置き、to へ移る
      • ログインの戻り先（tealus_login）: typ === "login" で、state が自分のクッキーに置いた値と一致すること。通ったら自分のログインを渡す

    ★ 入口はログインの札を落とすこと

    2 つの仕組みは同じ鍵を使います。入口が typ を見ないと、ログインの札でも入口を通れてしまいます。

    • state は小文字の 16 進 32 文字で作ってください。違う形だと、Tealus は先へ進みません
    • /sso/app-login は枠（iframe）の中では動きません。ブラウザのページとして移してください
    • 通行証は期限の中なら何度でも通ります（使い切りではありません）。リンクの下見が先に URL を取りに来ても、本人が開けるようにするためです
    • 入口のクッキーの作り方（期限・属性・.htaccess の書き方）と iPhone での注意は、本体リポジトリの docs/11 アプリの通行証 §2.1・§4 にあります

    記録¶

    本体の記録（info）に、出した・出さなかったが 1 行ずつ残ります。理由は外には言い分けず（どれも 404）、記録にだけ残します。札そのものは記録に書きません。

    行 例
    [app-pass] 出さない: room=… user=… index=… — <理由> 通行証を添えるが付いていない / 鍵が無い (portal.example.com) / ゲスト / 機械のアカウント
    [app-pass] 出さない: portal=… user=… — <理由> ホームのタブ
    [app-login] 出した: aud=… user=… / [app-login] 出さない: aud=… user=… — <理由> 許可表に無い aud / 鍵が無い

    決めていること¶

    • 部屋のアプリの通行証は、その部屋のメンバーにだけ出します。メンバーでない人は 403 です。ゲスト・機械・条件を満たさないときは 404 です
    • 部屋から外した人が、相手のサイトのクッキーでどれだけ通れ続けるかは、相手のクッキーの期限で決まります
    • 通行証には表示名（name）が入ります。札は URL に乗るので、相手のサイトのアクセス記録に名前が残ります
